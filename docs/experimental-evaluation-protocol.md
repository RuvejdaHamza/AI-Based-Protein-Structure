# Reproducible Experimental Evaluation Protocol

## 1. Purpose and scope

This protocol compares the implemented Simulated Annealing (SA), Genetic
Algorithm (GA), and hybrid GA + SA on the same 2D HP objective:

\[
E(S)=-\epsilon C_{HH}(S),\qquad \epsilon=1.
\]

It specifies inputs, run replication, budgets, controls, stopping rules, and
metrics. It contains **no experimental outcome claims**. All results must be
generated by running the protocol and retained with their run-level records.

The 2D HP model is a simplified lattice model; results on the real-sequence
fragments below are not claims of native biological structure prediction.

## 2. Benchmark inputs

Use the five required lengths \(N\in\{8,12,16,20,30\}\). A test case is one
unique HP string at one length. The main matrix has four synthetic HP cases
and four real-protein-derived cases per length: 40 cases total.

### 2.1 Synthetic HP cases

Construct each string deterministically from the following rules. Here,
\(a^k\) means \(k\) repetitions of letter \(a\); concatenate terms in the
displayed order. These patterns span hydrophobic-rich, polar-rich, balanced,
clustered, and alternating compositions.

| Case ID | Definition for each length \(N\) | Purpose |
|---|---|---|
| `syn_H70` | \(H^{\lceil0.7N\rceil}P^{N-\lceil0.7N\rceil}\) | H-rich, one long hydrophobic block |
| `syn_P70` | \(P^{\lceil0.7N\rceil}H^{N-\lceil0.7N\rceil}\) | P-rich, H residues concentrated at one end |
| `syn_balanced_blocks` | \(H^{\lfloor N/2\rfloor}P^{N-\lfloor N/2\rfloor}\) | Near-balanced composition, two blocks |
| `syn_alternating` | First \(N\) symbols of `HPHPHP...` | Dispersed H residues and frequent sequence alternation |

These are deterministic definitions, not sampled or observed experimental
results. The actual generated string and H/P counts must be written into the
run manifest for every case.

## 3. Replicates and random seeds

Run 10 independent replicates for each case and each algorithm:

\[
40\text{ cases}\times10\text{ replicates}\times3\text{ algorithms}
=1200\text{ runs}.
\]

Use these fixed replicate root seeds:

```text
1101, 2027, 3037, 4051, 5059,
6067, 7079, 8081, 9091, 10007
```

Derive one deterministic 32-bit seed for each run from
`(root_seed, case_id, algorithm_name, replicate)` using SHA-256. Do not use
Python's built-in `hash()`, whose value may vary between processes. Initialize
one random generator per run; never share a mutable RNG between algorithms.
SA starts from one independently generated valid structure; GA and hybrid
independently generate their configured populations. These are independent
seeded runs, not identically initialized runs; record initial energy and
available initial population statistics so initialization variability is
visible.

## 4. Computational budget and stopping policy

### 4.1 Primary budget: equal objective-evaluation cap

Give each run a common limit of **200 objective evaluations**, including initial
energy scoring. An evaluation is one calculation of the HP objective for a
valid structure that is not skipped as a duplicate. The GA and hybrid charge
initial population members and offspring evaluations to this limit. SA charges
its initial structure and every selected proposal evaluated by its incremental
energy tracker. In the hybrid, GA and nested SA share one `EvaluationBudget`;
the combined number of evaluations must never exceed 200.

Candidate evaluations, including initial scores, are counted by the shared
controller. Dataset preparation and CSV export are outside each timed
algorithm run. Keep invalid candidates separate: they do not receive energy
evaluations, but their construction/validation overhead is reflected in runtime
and invalid-candidate metrics.

Equal objective-evaluation limits are a reproducible search-work budget, but
are **not identical CPU instruction counts**. SA constructs a complete local
neighborhood per iteration, while GA may reject invalid offspring before
scoring. Report runtime, invalid candidates, duplicates, and algorithm-specific
counters alongside energy quality; do not claim equal evaluation counts imply
equal elapsed time or CPU work. Use 200 evaluations for the primary matrix and
record actual evaluations and termination reason for every run.

The shared controller must stop scoring at the limit and preserve the best
valid structure. A budget smaller than the initial GA population is invalid;
the runner rejects such a setting before starting the matrix.

### 4.2 Evaluation-budget sensitivity experiment

As a secondary analysis, run an evaluation-capped comparison on a preregistered
subset: all five lengths, `syn_H70` and `syn_alternating`, and `real_HBB` and
`real_CYCS` (20 cases total). Use all 10 root seeds and all three algorithms.
Test **100, 200, and 500 counted objective evaluations per run**, initial
scoring included. Apply the same generous timeout to all methods and report if
it binds. Keep the GA population no greater than the minimum 100-evaluation
budget.

This track compares quality at common objective-evaluation checkpoints; it is
not a claim of equal CPU work because candidate generation, collision
rejection, symmetry canonicalization, and full-neighborhood materialization
have different costs.

Keep all other settings fixed. These 1,800 sensitivity runs are additional to
the primary runs, not additional independent seeds. Do not pool budget tracks.

### 4.3 Stopping criteria

- The budget caps above are the primary stopping conditions.
- Disable target-energy stopping: no known global optimum is assumed for these
  cases.
- Disable no-improvement patience for the primary comparison; a plateau must
  not give one method a shorter effective budget.
- Set iteration/generation maxima high enough that they do not bind before the
  budget. Retain a large emergency upper bound and report if it is reached.
- Stop immediately on budget exhaustion or a fatal inability to create a valid
  initial population; do not silently reduce population size or replace
  failures with fabricated structures.
- Use the same valid-structure rules, HP mapping, \(\epsilon=1\), and local move
  definitions in every algorithm.

For SA, fix the geometric schedule at `initial_temperature=10`,
`cooling_rate=0.995`, `minimum_temperature=0`, with end, corner, and
crankshaft moves enabled. For GA, fix population size 20, tournament size 3,
crossover probability 0.8, mutation probability \(1/(N-1)\) per direction gene
(expected one mutation attempt per child), elitism 1, and symmetry reduction
off. Set `max_initial_attempts=100`, `max_offspring_attempts=2,000`, and
`max_generations=200`; configure SA and hybrid local-SA `max_iterations=200`.
Disable target energy and no-improvement stopping. The common budget
controller, not these limits, should stop normal runs. For the hybrid, use the
same GA settings; refine the best 20% every five
generations with SA using the same temperature schedule. Both parts share the
same budget. Record invalid and duplicate handling as implemented.

The project SA neighborhood currently removes symmetry-equivalent neighbors,
while GA symmetry reduction is configurable and disabled by default. Keep the
settings above fixed for a comparison of the current algorithms, explicitly
record this difference, and do not attribute any outcome solely to the search
strategy without this qualification. A stricter follow-up may harmonize
symmetry handling across all three methods before running.

### 4.4 Runtime and anytime reporting

Report elapsed wall-clock and process CPU seconds for each run, under a
recorded environment (CPU model, Python version, OS/runtime, Kaggle session
type, and whether the notebook was otherwise idle). Report best-so-far energy
at common evaluation checkpoints up to 200 calls. Runtime is an outcome, not
the equal-budget definition; it reveals differences in neighborhood
construction, invalid-genome rejection, and population management.

## 5. Parameters and environment to control

Record and hold fixed within each comparison:

1. Code revision or source archive hash, Python version, OS, CPU allocation,
   notebook runtime, and thread/process count. The algorithms use CPU-bound
   Python; do not give one method a GPU or extra workers.
2. Exact amino-acid input, UniProt accession/version or synthetic-generation
   rule, HP mapping, sequence length, and \(\epsilon\).
3. Budget definitions and whether initial scoring,
   duplicate candidates, invalid proposals, local refinement, and population
   initialization consume the budget.
4. The GA population, selection, crossover, mutation, elitism, retry limits,
   and symmetry setting; the SA cooling schedule, move set, and stopping
   criteria; the hybrid refinement fraction/frequency and local-SA settings.
5. Random seed derivation and independent RNG streams.
6. Structure-validity policy, duplicate policy, and handling of failed
   initializations or budget-exhausted runs.
7. Benchmark warm-up procedure, CPU timer (`time.process_time`), wall timer
   (`time.perf_counter`), memory method (if used), and output precision.

Do not tune parameters on the evaluation replicates. If tuning is required,
use a distinct pilot set of sequences/seeds, freeze the selected settings, and
report the pilot separately.

## 6. Metrics and required run-level output

For each run, save a machine-readable row (CSV or JSON Lines) containing:

- Case ID, length, source accession or synthetic rule, amino-acid sequence
  where applicable, HP string, H/P counts, replicate ID, root and derived
  random seeds, algorithm, configuration, and code/environment identifiers.
- Termination reason, run status, and whether the evaluation budget was
  exhausted.
- Best-so-far energy and contact count; also initial and final energies.
- Energy evaluations, generated candidate proposals, valid/invalid candidate
  counts, duplicates avoided, GA collision rejections, and local-search work.
- The evaluation count at the first stored convergence-history checkpoint
  reaching the final best energy.
- SA iterations/accepted/rejected moves; GA generations, diversity, and
  best/mean population energy; hybrid local-search calls/replacements and
  separately attributed GA/SA evaluations.
- Wall-clock seconds, process CPU seconds, and peak Python-tracked memory bytes
  (via an independent `tracemalloc` session per run); this is not process RSS.
- Final best structure coordinates or relative directions, followed by an
  independent validity check and recomputed energy.

Primary quality measures:

1. Best energy/contact count at the common 200-evaluation budget.
2. Best-so-far energy versus objective evaluations.
3. Best-so-far energy versus wall-clock and process CPU seconds.
4. Across-replicate median, mean, standard deviation, interquartile range, and
   95% confidence interval for best energy.
5. Per-case and per-length invalid-proposal rate, duplicate rate, and valid
   structure rate.
6. Objective evaluations and wall time to reach a predeclared energy threshold
   only if a threshold is set before runs. Do not call it optimum attainment
   unless the optimum is independently known.
7. For GA/hybrid, population diversity and best/average energy histories; for
   SA, acceptance rate and current/best energy histories.

The convergence evaluation count is checkpoint-grained: SA records each
iteration, while GA and the hybrid record each completed generation. It is not
an exact evaluation timestamp for improvements that occur within a generation.
Candidate counts report generated proposals; a valid candidate can be a
duplicate and is still included in the valid count.

Energy is non-positive and is lower when more non-consecutive H-H contacts are
found. Report raw best energy and contact count; optional normalization by
length must be reported in addition to, not instead of, raw values. Do not
compare energy values across different HP sequences as if they shared the same
optimum.

## 7. Statistical analysis

Treat each sequence case as a distinct problem instance. Show per-case results
first; summarize separately by length and by synthetic/real category. The four
real proteins are selected examples, not a representative sample of all
proteins.

For each case, treat the algorithms' independently seeded runs as independent
samples. Report medians and interquartile ranges, bootstrap 95% confidence
intervals for differences in best energy, and an independent-sample test (for
example Mann-Whitney U or a permutation test) when its assumptions are
appropriate. Use paired tests only if a future design actually shares and
records matched starting conformations across methods. Correct families of
per-case comparisons for multiple testing (Holm method). Include effect sizes
and confidence intervals; do not infer a meaningful difference from a p-value
alone. If a method fails to produce a valid initial population, report the
failure rate and do not discard it silently.

Energy distributions can be discrete and tied; inspect differences and report
the tie handling used. Do not treat repeated seeds or nested prefixes from one
accession as independent biological samples. Aggregation across cases is
descriptive unless a suitable hierarchical model is specified.

## 8. Reproducibility checklist

Before reporting results, verify:

- [ ] All 40 case IDs and exact input strings match this protocol.
- [ ] Real FASTA metadata, retrieved sequence versions, and input hashes are saved.
- [ ] Each case/algorithm has all 10 planned seed runs or documented failures.
- [ ] Shared objective-evaluation budgets are enforced and counters audited.
- [ ] Parameter settings, software/runtime environment, and timer are recorded.
- [ ] Every returned structure passes independent self-avoiding-walk validation.
- [ ] The reported energy matches an independent full energy recomputation.
- [ ] Run-level results and analysis scripts are retained; no results are
      manually entered or inferred from benchmark examples.
- [ ] No unrun result, expected trend, or hypothesis is presented as a
      measurement.
